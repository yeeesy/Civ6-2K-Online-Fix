# 开发与发布说明

本文面向希望构建、审阅或贡献代码的开发者，记录公开且长期有效的维护规则。

## 版本与构建

产品版本只在根目录 `version.json` 中维护。构建脚本会由它生成程序身份与 Windows 版本资源，并在构建结束时核对结果。

需要 Windows 10/11、Visual Studio 2022 C++ x64 工具链、Windows SDK 和 PowerShell：

```powershell
& '.\build.ps1' -Analyze
& '.\build\Civ6_2K_Online_Fix.exe' --self-test
& '.\package.ps1'
$ver = (Get-Content version.json -Raw | ConvertFrom-Json).Version
& ".\dist\Civ6_2K_Online_Fix_${ver}\verify_hashes.ps1"
```

发布包还应从包内 `source` 目录在另一绝对路径重新构建，并确认重建程序与包内程序逐字节一致。

## 不得放宽的边界

- 只有内置且明确允许的精确 Build Profile 可以进入写入路径。
- 新游戏构建在获得独立验证前只能做只读识别。
- 预检结果不能代替运行时身份校验；目标进程和相关映像必须在写入前再次确认。
- 发布与恢复都必须确认目标位置仍由预期值占有，并检查写入及回读结果。
- 页面保护恢复和指针恢复必须分别判断，不得用其中一个结果代替另一个。
- 只恢复仍属于当前会话的改动，不覆盖其他组件的改动。
- 可能仍被游戏执行的保护代码不得在游戏存活时释放。
- GUI 只负责展示状态和发出请求，不持有目标进程资源的所有权。

任何涉及进程写入、身份判断、所有权或清理生命周期的修改，都必须先增加失败用例，再实现改动并运行完整测试。

## 新游戏构建支持

在维护者的电脑安装游戏更新后，可运行 `python analyze_build.py --bin-dir "<Win64Steam 目录>" --report candidates.json`。工具只读磁盘上的两个 EXE，按 PE 导入和函数结构定位锁调用。零个或多个匹配都不输出推荐位置。它不修改源码或游戏，也不会生成可写配置；服务对象的字段含义、运行库布局和实机行为需分别核实。报告不包含游戏文件或绝对安装路径。

新增兼容配置时，应先通过只读诊断确认官方游戏版本、渠道、EXE 名、大小和 SHA-256，并独立验证所需的 PE、运行库及目标位置关系。仅凭版本号、文件名或外部配置不得开启写入。

请勿提交版权游戏文件或原始个人日志。诊断资料必须删除本机用户名和路径、PID、内存地址、账号标识、凭据及无关哈希。静态分析得到的候选配置保持只读，完成所需的正向、取消、超时、未知构建和并发变化验证后，才可考虑提升为受支持状态。

对已登记为只读候选的构建，可在启动游戏前运行 `Civ6_2K_Online_Fix.exe --observe-candidate`，再从 Steam 选择渲染器。这个入口只读已校验进程的服务和锁计数，不安装 Guard。终端只显示相对时间与聚合结果。捕获到样本不代表已修复，应另外对照游戏主菜单状态。

## 发布检查

正式发布前至少完成：

1. 检查 `version.json`、README、更新记录和包名一致；
2. 在干净环境执行警告即错误构建、全部测试、MSVC `/analyze` 和离线自检；
3. 生成发布包并验证完整文件集合与 SHA-256 清单；
4. 从包内源码异路径重建并进行逐字节比较；
5. 扫描公开源码与归档，确认无个人路径、账号数据、凭据、原始日志、游戏文件或内部工作资料；
6. 确认 GitHub Actions 使用最小权限，第三方 Action 固定到完整提交；
7. 正式发布 ZIP、外部 SHA-256 和供一键更新使用的签名元数据。

当前发布未使用商业 Authenticode 代码签名，因此 SmartScreen 的未知发布者提示属于预期现象。不要使用自签名证书伪装成公开信任，也不得把任何签名私钥放入仓库、源码包或 CI 日志。

## 诊断隐私

工具不会自动上传诊断资料。优先使用“反馈问题”打开的脱敏 TXT；`--diagnose` 输出和原始 JSONL 只在本机排查时使用。

## 更新包签名与安装

构建 1.2 需要 MSVC x64、Windows SDK、Visual Studio 的 Roslyn C# 编译器及 .NET Framework 4.8 引用或运行库。更新助手作为资源嵌入 EXE，客户端无需安装额外的命令行工具。

最终正式 ZIP 完成异路径重建和校验后，发布者在保管密钥的 Windows 账户下用 PowerShell 7 执行：

```powershell
& './sign_update.ps1' -Archive "./dist/Civ6_2K_Online_Fix_${ver}.zip"
```

将生成的同名 `.update` 与 ZIP、`.zip.sha256` 一同上传到对应正式版本的 Release。它绑定项目、版本、包长度、包摘要和程序摘要。私钥由当前用户的 Windows CNG 软件密钥存储保管，不可导出；仓库仅含 `src/update-public-key.xml`。此签名用于工具更新，与商业 Authenticode 签名分开。若迁移账户或重装机器，须在旧密钥可用时安排公钥轮换。签名不可用时不发布可自动安装的更新。

更新针对便携目录中的主 EXE：仅取签名清单对应的程序，不展开包内其他路径。完整源码和文档仍随每版 ZIP 提供。下载包中的 SHA256SUMS 用于校验原始解压内容；主程序更新后，应使用对应版本的新 ZIP 检查完整发行包。更新助手等旧工具正常退出才原子替换；新窗口在开始修复会话之前确认启动，失败时使用旧程序回退。
